# 雪球雷达 · 无人值守版（油猴脚本）

> 替代已封禁账号的 Playwright 方案。**打开即后台常驻运行，无需任何点击。**

---

## 一、为什么不用 Android 模拟器

我查了雪球官方技术文档《APP 攻防 100 讲》，App 端反爬是**五层嵌套**：

1. 设备指纹固化
2. SSL Pinning 强制校验（需 Frida / Magisk 绕过，随版本失效）
3. 请求体 AES+RSA 混合加密
4. 行为埋点反模拟
5. 服务端实时风控模型

模拟器会命中第 4 层「反模拟」——**平台可能直接返回虚假数据，你无法分辨抓到的是真数据还是诱饵**。加上模拟器共享出口 IP，账号风险反而更高。

Web 端完全不同：我实测雪球用的是**阿里云 WAF**（响应头 `Set-Cookie: acw_tc`），只拦裸 HTTP 请求，**真实浏览器天然通过**。所以：

| | Playwright 裸跑 | 油猴脚本 | 模拟器 |
|---|---|---|---|
| 过 WAF | 靠 stealth 注入，勉强 | 天然通过 | 不适用 |
| 账号风险 | 高（指纹+定时+翻页特征） | 极低（跑在你自己浏览器里） | 高 |
| 维护成本 | 高（跟版本） | 低 | 极高（跟版本） |
| 封号后恢复 | 换号即可，代码不改 | 换号即可 | 换号即可 |

**结论：油猴脚本是最优解。** 模拟器投入产出比极低，不建议。

## 二、实测发现（2026-10-22，Chrome 140 / 雪球现行前端）

这几条推翻了网上多数教程和你原项目 README 里的部分说法，脚本已按实测修正：

| 发现 | 影响 |
|---|---|
| `xq_a_token` 是 **HttpOnly**，`document.cookie` 读不到 | 不能用 cookie 判断登录态 → 改用**接口探针** |
| `/statuses/comments.json` 游客态返回 `error_code 10022 用户未登录` | 评论接口**必须登录**（你原 README 说"公开"是错的） |
| `/v4/statuses/comments.json` 已 **404** | 网上流传的 v4 路径已失效，别用 |
| 前端上了 CSS Modules，类名带随机哈希（`style_timeline__item__main_lHD`） | `.timeline__item` 固定选择器**已失效** → 用 `[class*=...]` 子串匹配 |
| 未登录访问 `/<post_id>` 会被**重定向回首页** | 被动 DOM 模式也必须登录 |
| 热门列表 `items[].id` 是序号（973959），真实帖 id 在 `original_status.id` | 过滤逻辑必须取 inner id |
| 裸 curl 必吃 110KB WAF JS 挑战页，一个 cookie 都不下发 | **python-requests 永远过不了 WAF** |
| `comments.json` 按时间**升序**返回（`page=1` = 最早的 20 条；用历史库核对 id 与 created_at 递增证实） | `page=1..N` 抓到的全是**最老、时效性最差**的评论，而人在页面上看的是最新/最热的 → 改为「第 1 页探 maxPage，之后抓尾部页」，请求次数不变 |

## 三、安装（3 步）

### 1. 装油猴
你机器上**已经装了 Tampermonkey**（Chrome 扩展 `dhdgffkkebhmkfjojejmpbldmpobfkfo`），跳过此步。

### 2. 装脚本
打开 Tampermonkey 面板 → 新建脚本 → 粘贴 `xueqiu-radar-auto.user.js` 全文 → 保存。

### 3. 配 Worker（设置面板）

打开雪球任意页面，左下角出现「雪球雷达 v3」面板 → 点「设置」，会弹出设置对话框：

| 字段 | 说明 |
|---|---|
| **上传地址** | `https://你的域名/api/ingest`（完整 URL） |
| **上传 Token** | 与 Worker 环境的 `INGEST_TOKEN` 一致（输入框是 `password` 类型，界面上不可见） |
| 测试连通性 | 点一下立即验证地址/token 对不对（200 有效 / 401 token 错 / 404 接口不存在） |
| 保存（自动自检） | **保存即自检 + 自动跑一轮**，几秒内知道成没成，不用等 1.5~4 小时 |
| 导出配置 | 把地址+token 复制到剪贴板，方便在另一台设备粘贴 |
| 导入配置 | 粘贴上面导出的 JSON，自动填表 |

配好点「保存」就完事了。**不需要点任何其他按钮**——脚本打开即自动开始。

### 抓取参数（板块 / 帖数 / 阈值）

| 字段 | 默认 | 说明 |
|---|---|---|
| **板块** | `recommend,hot,follow` | 可选 **recommend**（推荐）/ **hot**（热门）/ **follow**（关注），逗号分隔。**默认三个全开** |
| **每轮总帖数** | 12 | 按启用板块**均分**：2 个板块各 6 帖、3 个板块各 4 帖。加板块**不增加**请求量 |
| **每帖页数** | 2 | 每页 20 条评论（上限 3 页） |
| **打分阈值** | 5 | 低于阈值不进候选池 |

> **关于「关注」流（2026-10-23 新增，默认启用）**
>
> 第三个源，默认就开（老配置升级时会自动把 `follow` 补进板块，只补一次）。
> 雪球时间线接口改版频繁，脚本内置 3 个候选路径逐个尝试，第一个能取到帖子的
> 会自动记住；**取不到只跳过该板块，推荐/热门照常跑**，不会拖垮整轮。
>
> 失败后有 **6 小时冷却**，不会每轮都去试 3 个接口（避免白费请求、加重风控）。
>
> 想确认能不能用：油猴菜单 →「测试「关注」流接口」，面板日志会逐条列出每个路径的结果。
> 如果全是 0 条，多半是该账号还没关注任何人（关注几个股票/大 V 再测）。
> 不想要这个源：设置里把板块改回 `recommend,hot` 即可，之后不会再被加回来。

### 保存后会发生什么（几秒内就有结果）

点「保存」时脚本会自动做两件事：

1. **上传通道自检** — 走与真实上传**完全相同**的鉴权与网络路径（`POST /api/exists`），
   但不写入任何线索数据（只是查存在性），不会污染数据库。
   - 成功 → 日志「✓ 上传通道验证通过（123ms）」
   - 失败 → **对话框不关闭**，就地显示原因，可直接改：
     `✗ Token 不正确（401）` / `✗ 接口不存在（404）` / `✗ 网络不通`
2. **自动跑一轮**（首次配置时）— 真实抓一次并上传，面板状态栏变成
   「上传 上传正常 · 成功 1 次 · 末次 18:55:38」

> 为什么要做这个：否则保存配置后要等下一个轮次（90~240 分钟）才知道能不能上传，
> 体验上等于「保存后一片空白」。

### 面板上的上传状态（第二行）

```
上传 上传正常 · 成功 3 次 · 末次 18:55:38     ← 绿色
上传 上传失败 2 次 · 点「设置」测试连通性        ← 红色

上传 未配置上传地址/Token · 点「设置」           ← 红色
```

> **关于「不暴露 Worker 地址」**
>
> 脚本源码里**不写死任何 Worker 地址和 Token**（`url` / `token` 默认都是空字符串），
> 全部存在浏览器本地（`GM_setValue`），只有你自己的浏览器能看到。
> 因此这个脚本可以安全地提交到仓库或分享给别人 —— 别人装上后自己填自己的地址。
>
> 面板日志里也只显示主机名（不显示完整路径），避免截图分享时泄露。

## 四、无人值守是怎么做到的

| 机制 | 实现 |
|---|---|
| **自动启动** | 页面加载即跑，`autoStart: true` |
| **登录自愈** | 未登录 → 每 15 分钟自动探针重试，登录后立即恢复，无需重启 |
| **轮次调度** | 每轮 150–240 分钟随机间隔（可配），跨天/跨会话用 `GM_setValue` 持久化 |
| **夜间停抓** | 23:00–07:00 自动零请求 |
| **会话续命** | 每 45 分钟自动刷新页面，避免长连接空转被判定 |
| **错过补跑** | 标签页休眠/唤醒后，检测到过点立刻补跑（见下方说明） |
| **多标签页协调** | 多个雪球标签页只让一个主控抓取，其余观察，避免重复请求 |
| **幂等保护** | `window.__XUEQIU_RADAR_V3__` 防止重复注入 |
| **失败自愈** | WAF → 退避 3–7 小时；账号受限 → 退避 12–24 小时并自动切号；网络错误 → 指数退避重试 |
| **连续空保护** | 连续 3 轮抓到 0 评论 → 判定异常，主动降频 |
| **账号轮换** | 账号池管理，遇限自动切下一个账号 |
| **开机自启** | `启动雪球雷达.bat` 放到「启动」文件夹 |

### 关于日志里的「◉ 页面重新可见」

**这不是错误，是无人值守能成立的关键机制。**

Chrome 会对**后台标签页的定时器做节流**，甚至直接冻结（Memory Saver）。
你切到别的标签页或最小化窗口后，`setTimeout(loop)` 可能被推迟很久才触发。

脚本用**绝对时间戳** `ST.nextAt` 判断是否错过了轮次：

```
[18:43] ⏰ 下一轮 1 小时 35 分 后
   ↓ 你切走标签页，Chrome 开始节流定时器
   ↓ 2 小时后你切回来
[18:45] ◉ 页面重新可见 · 错过了 120 分钟的轮次，立即补跑
[18:45] ▶ 新一轮（账号：当前浏览器账号）
```

没有它的话，切走一天回来可能一整天都不抓。

**会不会重复抓 / 重复上传？** 不会。三个触发点都过同一道门：

| 触发点 | 触发时机 | 互斥条件 |
|---|---|---|
| `setTimeout(loop)` | 到点 | `if (ST.running) return` |
| `visibilitychange` | 切回标签页 | `!ST.running && !ST.stopped` |
| `pageshow` | 从缓存恢复（`e.persisted`） | `!ST.running && !ST.stopped` |

`ST.running` 在 `loop()` 开头置 `true`、`finally` 里置回 `false`。
JS 单线程 → 两个入口不可能同时进入。补跑结束时会 `scheduleNext()` 重置 `nextAt`，
所以下次切回不会再次补跑。

实测验证（`tools/test_visibility.py`，真实 Chrome）：

```
人为把 nextAt 设为 120 分钟前 → 触发 visibilitychange
  ✓ 正确触发补跑
  ✓ 补跑期间重复触发 5 次，「立即补跑」只出现 1 次
  ✓ 补跑后 next_run 更新到 97 分钟后（不会重复触发）
  ✓ 上传请求数 = 1（无重复上传）
  ✓ 无 JS 错误
```

即便万一真的重复上传，服务端 `clue_id` 唯一索引 + UPSERT 也会兜住（见去重章节）。

### 保号硬约束（脚本内部强制，UI 改不动）

```
每板块帖子 ≤ 10    每帖评论页 ≤ 3    轮次间隔 ≥ 30 分钟（2026-10-23 由 90 下调）
帖子间随机延迟 3.2–7.8s    翻页延迟 2.1–3.6s    夜间 23:00–07:00 零请求
```

> ⚠ 间隔 < 90 分钟会明显增加风控/封号概率。脚本允许设到 30 分钟，但保存时会给出警告，
> 面板日志里会留一条 `⚠ 间隔 N 分钟偏短…`。建议仍用 150–240 分钟。

## 六、多账号轮换（重要）

**油猴脚本的登录态 = 当前浏览器的登录态。** 所以：

1. **多账号隔离**：为每个账号建一个 Chrome 配置文件
   ```
   chrome://settings/ → 左侧「个人资料」→ 添加 → 命名如「雪球A」「雪球B」
   ```
   每个配置文件分别登录一个雪球账号，分别打开雪球页面，脚本会各自运行。
2. **脚本内账号池**：点「账号池」添加备注名（只是标识不同账号）。当某账号被限，脚本自动切到下一个备注。
3. **注意**：切换备注**不会**切换实际登录账号——你需要在对应 Chrome 配置文件里重新登录。

> 建议：**不要**把账号池功能当作真正的换号手段。真正换号靠不同的 Chrome 配置文件。

## 七、去重与集中写入（重要）

### 5.1 原方案的漏洞

原 `clues` 表主键是 `(round_id, clue_id)`，**只能保证「轮内幂等」**。而 `round_id` 每轮都变——雪球热门帖会在多轮抓取中反复出现，同一条评论（`clue_id` 相同）会在不同 `round_id` 下插入多行。

我实测复现了这个缺陷：

```
场景：评论 c1 在第 1 轮和第 2 轮都被抓到
  clues 总行数      = 5
  唯一 clue_id 数   = 4
  >>> 冗余行数      = 1   ← 存在重复!
```

后果：前端列表出现重复条目，且每轮重复消耗 D1 写入额度（免费版每日 10 万行写）。

### 5.2 三层去重

| 层 | 位置 | 作用 |
|---|---|---|
| **① 客户端** | `seenSet`（`GM_setValue` 持久化） | 已上传的 `clue_id` 不再重传 |
| **② 客户端探针** | `POST /api/exists` | 上传前问服务端"哪些已在库"，只发新的 |
| **③ 服务端兜底** | `clues.clue_id` 唯一索引 + UPSERT | **无论客户端怎么做，库里保证唯一** |

第 ③ 层是关键——即使客户端的 `seenSet` 被清空、即使换设备、即使 exe 和油猴同时跑，数据库也不会出现重复行。

### 5.3 重复线索怎么处理

不是丢弃，而是**走 UPSERT 只更新计数**：

```sql
UPDATE clues SET
  last_seen_round = ?,              -- 最近一次命中轮次
  hit_count = COALESCE(hit_count,0) + 1,   -- 累计命中次数
  like_count  = MAX(like_count, ?),       -- 点赞数取较大值（会增长）
  reply_count = MAX(reply_count, ?)
WHERE clue_id = ?
```

- `round_id` 保留**首现轮次** → 前端的「来源」标签不变
- `first_seen_round` / `last_seen_round` / `hit_count` 记录完整轨迹
- 前端线索卡片显示 `×N` 标记（`hit_count > 1`），直观看出"这条在热门帖里反复出现"

### 5.4 集中写入

**服务端**：把一轮的所有 INSERT/UPDATE 合并成尽量少的 `DB.batch` 事务。

```
250 条候选 → 旧实现 251 次事务 → 新实现 3 次事务（减少 99%）
```

**客户端**：候选先入持久化缓冲，攒够才发。

| 参数 | 默认 | 说明 |
|---|---|---|
| 攒批阈值 | 30 条 | 攒够就上传 |
| 最长等待 | 90 分钟 | 即使没攒够也发（避免滞留） |
| 缓冲上限 | 300 条 | 超出强制发（防内存膨胀） |

缓冲**持久化到 `GM_setValue`** → 浏览器意外关闭也不丢，下次启动自动补传。页面关闭时用 `sendBeacon` 兜底。

面板实时显示缓冲条数，也可点「刷新缓冲」手动触发。

### 5.5 实际效果（本地 SQLite 实测）

```
第1轮：候选 20 → 实发 20，跳过 0
第2轮：候选 25 → 实发 10，跳过 15
第3轮：候选 20（全重复）→ 实发 0，跳过 20  ← 零写入

clues 表：总行 30，唯一 30  ✓ 无重复行
命中分布：1 次→10 条，2 次→5 条，3 次→15 条

行写入减少 54%   DB.batch 事务减少 99%
```

### 5.6 部署

```bash
cd xueqiu-radar
npm i -g wrangler
# 或直接双击 migrations/部署去重升级.bat
```

它会先应用迁移 `0009`（含历史重复行清理），再部署新版 Worker。**顺序不能反**——迁移失败就中止，不部署 Worker，避免版本不匹配。

> ⚠️ 迁移 `0009` 会删除历史重复行（保留最早出现的那条）。这是有意的清理，不影响已在前端看到的线索内容。

### 5.7 新增接口

| 接口 | 用途 | 鉴权 |
|---|---|---|
| `POST /api/exists` | 批量查询哪些 `clue_id` 已在库 | Bearer Token |
| `POST /api/hits` | 上报重复命中（只更新计数） | Bearer Token |

两个接口都要求 token 鉴权，不会泄露数据。

## 八、旧版 EXE 方案踩过的坑（已移除，存档备查）

旧版是 Python + Playwright 打包的 `xueqiu.exe`，2026-10-22 因账号被风控封禁而移除。
以下几处当时与实测不符，是封号的间接原因，改用油猴脚本后天然规避：

1. **登录检测方式** — 旧 `stealth.py` 的 `_LOGIN_STATE_JS` 用 `document.cookie` 找 `xq_a_token`，
   但它是 HttpOnly，**永远检测不到** → 判定逻辑形同虚设。
   油猴脚本改用接口探针：
   ```js
   // 有 comments 数组 = 已登录；error_code 10022 = 未登录
   const r = await xqJson("/statuses/comments.json?id=<真实帖id>&page=1&count=1");
   ```
2. **热门列表取 id** — `items[].id` 是序号，真实帖 id 在 `original_status.id`（或 `data` 字段的 JSON 里）。
3. **评论接口必须登录** — 旧 README 写「公开接口、无需登录」是错的。
4. **CSS Modules** — 固定类名选择器（`.timeline__item` / `.comment__content`）在现行前端已失效，用 `[class*=...]`。
5. **v4 接口路径** — `/v4/statuses/comments.json` 已 404，不要照抄网上教程。
6. **Playwright 指纹残留** — 需注入 stealth 脚本伪装 `navigator.webdriver`，但 CDP 层面的痕迹无法完全抹除。
   油猴脚本跑在真实浏览器里，**零伪装需求**。
7. **登录态获取成本** — 旧方案要复制 Chrome Profile，受 Chrome 127+ App-Bound Encryption 限制，
   必须人工首次登录。油猴脚本直接复用当前浏览器登录态。

## 九、验证记录

我做了三层验证：

**① 链路诊断**（curl）— 确认裸 HTTP 必吃 WAF 挑战页，`Set-Cookie: acw_tc` 是浏览器 JS 执行后才有。

**② 真实浏览器实测**（系统 Chrome + Playwright）— 确认接口路径、错误码、cookie 属性、DOM 类名规则。

**③ 全链路端到端**（真实 Chrome + 真实抓取逻辑 + 真实 HTTP 上传）— 用真实捕获的接口样本做桩：

```
[17:10:10] 共 32 条评论，打分中…
[17:10:10] ▲ 候选 5 条（阈值 5）
[17:10:11] ✓ 上传成功 · 候选 5 条
[17:10:11] ⏰ 下一轮 1 小时 35 分 后（18:45:08）

mock worker 实际收到 POST: 1   ← 无重复上传
```

打分正确性抽样：

| 评论 | score | tags |

payload 契约校验：`missing_fields: []`、`bad_time_ids: []`（时间串均可被 Worker 解析）。

**④ 去重与集中写入验证**（用 `node:sqlite` 真实模拟 D1，跑 Worker 的实际 `ingest` / `handleExists` / `handleHits` 代码）：

## 十、风险提示

- 雪球服务协议明确禁止爬虫与绕过安全机制。**低频、低量、自用**是相对安全的区间，但仍有封号可能。
- 脚本已把频率压到接近真人水平，但不能保证 100% 不被风控。
- 建议先用新号跑几天观察，确认稳定再上主力号。
- 命中 WAF/限制时脚本会自动退避，**不要手动点「立即跑一轮」硬刚**。
